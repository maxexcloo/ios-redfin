# iOS Redfin

- Scope is Pixel 5 / redfin / SM7250. README owns status from this phone's identified evidence, kept separate from upstream claims; experiment history stays in commits and ignored `work/boot/`/`logs/` artefacts.
- `xnu/patches/` owns kernel changes: save a numbered patch from the patched build tree with upstream provenance, and check existing numbers before importing another branch (upstream workstreams reuse 1048/1049). `shim/soc.args` owns live device-tree facts, `tools/` host tools, `tests/` host tests and `phone/` iOS userland. Build success does not establish boot or rendering correctness.
- Host tools keep `redfin-*` names; boot-arg names (`flame*`, `sweet*`), ADT/IOKit identifiers, phone binaries and bundle names are ABI and keep upstream names.
- Bring-up uses temporary `fastboot boot` images. `tools/redfin-boot.sh` must verify a single redfin device so other ports' phones are untouched. Installing the root writes `userdata`; confirm data-erasing steps immediately beforehand. Never flash ABL, XBL, TZ, modem or calibration partitions for bring-up, and never relock modified software.
- Pixel ABL requires boot header v3, an LZ4 Image with text offset 0x80000 and an AVB footer padded to 96 MiB, and takes the DTB from the installed `vendor_boot`. Preserve the top 17 MiB of userdata for logs; do not read or write `/dev/ufsroot0` from iOS userspace (physio panic).
- Changing ADT camera/flash capabilities requires invalidating MobileGestalt's CacheVersion. Keep the working no-camera UI profile; camera advertisement requires its capture server and plug-in. Preserve root/mobile numeric ownership when copying or mounting the root image, and replace loaded dylibs by rename.
- Keep Apple material, translated shaders, vendor firmware, phone trees/logs, partition dumps and credentials out of Git and tool output; inspect only the data the task needs.
- Run `mise run check`; `mise run build -- PAYLOAD OUT` builds the shim. Keep thermal protection enabled, and validate rendering on the phone by delivered frames and interaction, not panel Hz or idle thread counts.
